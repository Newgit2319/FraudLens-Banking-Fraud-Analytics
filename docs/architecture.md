# FraudLens – System Architecture

## 1. Project Overview

FraudLens is a Banking Fraud Detection & Risk Analytics Platform that combines:

- Python-based data generation and ETL
- MySQL relational database
- SQL-based fraud analytics
- Machine Learning-based fraud risk prediction
- Streamlit-based interactive dashboard

The system processes banking transaction data, stores structured banking entities in MySQL, performs fraud and risk analysis using SQL, generates ML-based risk predictions, and presents the results through an interactive web dashboard.

The major objectives of the system are:

- Store banking data in a structured relational database.
- Perform fraud-related analysis using SQL.
- Maintain fraud-related transaction and alert information.
- Train a machine learning model for fraud-risk prediction.
- Provide transaction investigation and fraud alert capabilities.
- Present analytical and ML results through an interactive dashboard.

## 3. System Components

### 3.1 Dataset Layer

The project uses a PaySim-based banking transaction dataset as the transaction source.

The transaction data provides the base information required to construct the FraudLens banking transaction records.

The source data is processed using Python before being stored in the project's structured database.

---

### 3.2 Python Data Processing and ETL Layer

Python is used to prepare and transform the data required by the FraudLens system.

The processing layer performs tasks such as:

- Loading transaction data.
- Extracting unique customer and account identifiers.
- Creating mappings between source identifiers and generated banking identifiers.
- Generating structured banking entities.
- Preparing transaction records.
- Creating fraud-related records.
- Exporting processed data to CSV files.
- Loading the generated CSV files into MySQL.

The major data entities generated by the pipeline include:

- Branch
- Customer
- Account
- Device
- BankUser
- FraudRule
- BankTransaction
- LoginLog
- FraudAlert
- AuditLog

---

The SQL analytics layer provides information such as:

---

### 3.5 Machine Learning Layer

The machine learning layer uses a Random Forest classification model to predict fraud risk.

The model is trained using transaction, behavioral, device, and time-based features.

The features include:

- Transaction amount
- Log transaction amount
- Transaction type
- Channel
- City
- Device type
- Operating system
- Trusted-device status
- Transaction hour
- Transaction day of week
- Weekend indicator
- Night-time indicator
- High-value transaction indicator
- Sender transaction count
- Sender average transaction amount
- Device transaction count
- Account-pair frequency

The target variable is:

```text
fraud_flag
```

The existing `fraud_flag` and `fraud_score` fields are not used as model input features in order to avoid target leakage.

The trained Random Forest model uses:

```text
n_estimators = 300
max_depth = 12
min_samples_leaf = 2
class_weight = balanced
random_state = 42
```

The dataset is divided into training and testing sets using a stratified 80/20 split.

## 7. Fraud Risk Classification

The ML prediction pipeline produces a fraud probability for each transaction.

The probability is used to assign a risk category.

The categories used by the application are:

```text
Low
Medium
High
Critical
```

The model-generated predictions are kept separate from the original database fraud fields.

This allows the project to distinguish between existing transaction fraud labels and machine-learning-based risk predictions.

## 10. System Execution Flow

The complete execution sequence of FraudLens is:

### Step 1 – Prepare Dataset

The PaySim-based transaction dataset is placed in the `dataset/` directory.

### Step 2 – Generate Structured Data

The Python data-generation pipeline processes the source transaction information and creates the required banking entities.

### Step 3 – Export CSV Files

The generated entities are exported into CSV files in the `output/` directory.

### Step 4 – Load MySQL Database

The database-loading script inserts the generated CSV records into the `fraudlens` MySQL database.

### Step 5 – Create SQL Analytics

The SQL analytics script creates the required analytical views.

### Step 6 – Train Machine Learning Model

The ML training script performs feature engineering, trains the Random Forest classifier, evaluates the model, and saves the trained model and evaluation results.

### Step 7 – Generate ML Predictions

The trained model generates fraud probabilities and risk classifications for the transaction dataset.

The predictions are stored in:

```text
output/ML_Predictions.csv
```

### Step 8 – Start Streamlit Dashboard

The Streamlit application is launched and connects to the MySQL database.

```bash
streamlit run scripts/app.py
```

### Step 9 – Analyze Fraud Risk

The user can:

- View overall fraud statistics.
- Investigate individual transactions.
- Review fraud alerts.
- Analyze ML-generated risk predictions.

### Step 10 – Final Output

FraudLens provides a unified platform combining:

```text
Data Processing
      +
Relational Database
      +
SQL Analytics
      +
Machine Learning
      +
Interactive Dashboard
```

This architecture demonstrates the integration of Python, SQL, machine learning, and data visualization within a single fraud analytics application.
